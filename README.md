# Ledgerly — учёт доходов и расходов

Счета, доходы и расходы с календарными датами; баланс и денежные показатели рассчитываются по сохранённым операциям.

## Возможности

- Создание счетов, фильтры, изменение статуса и удаление.
- Проверка сумм, дат, категорий и описаний доходов и расходов.
- Баланс, движение средств за шесть месяцев, рост дохода, квартальные цели и атомарный CSV-импорт/экспорт.

## Стек и устройство

JavaScript, Express, Zod, встроенный SQLite в Node.js и интерфейс на HTML/CSS.

## Ключевые решения

- `money.js` проверяет точность минимальных денежных единиц, `finance.js` суммирует через BigInt. Миграция `amount_cents` сохраняет исходный REAL-столбец; неоднозначная точность старых сумм откатывает миграцию.
- Одна операция ограничена 1 млрд рублей, суммарные доходы, расходы и денежный диапазон — 1 трлн рублей, включая будущие записи. Превышение даёт 409 с откатом и сохраняет точность JSON до копейки.
- Оплаченный счёт учитывается в доходе один раз. Смена статуса или удаление меняет баланс; будущие операции не увеличивают сегодняшние средства.
- Редактирование и мягкое удаление требуют прочитанную версию. Условный UPDATE предотвращает потерю изменений; при 409 черновик остаётся. Удалённая запись сохраняется в БД, но исключается из отчётов.
- CSV ограничен по размеру и числу строк/полей; при экспорте экранируются формулы. Поиск хеша импорта и запись выполняются внутри BEGIN IMMEDIATE. Повтор не отменяет последующие изменения; другой документ с занятым UUID получает 409.
- Триггеры проверяют суммы, даты и типы операций. Изменения схемы атомарны; начальные записи добавляются только в новую БД. Проверки Host и Origin блокируют подмену хоста и межсайтовые изменения.

## Локальный запуск

Node.js 24.18.0 и pnpm 11.7.0; версии закреплены в файлах проекта.

```bash
npm install --global pnpm@11.7.0
pnpm install --frozen-lockfile
pnpm start
```

Откройте `http://localhost:4300`. Сервер по умолчанию слушает 127.0.0.1. Для разработки доступен `pnpm dev`.

## Настройки

Параметры перечислены в [.env.example](.env.example). `pnpm start` использует окружение процесса и не загружает файл автоматически. После копирования `.env` его можно загрузить явно: `node --env-file=.env server.js`.

## Данные и обновления

SQLite хранится в `data/ledgerly.db`. Инициализация создаёт или обновляет схему. Перед обновлением сохраните резервную копию; удалять БД вместо миграции не нужно.

## Проверки

```bash
pnpm lint
pnpm format:check
pnpm test
pnpm test:contract
pnpm test:upgrade
pnpm exec playwright install chromium
pnpm test:e2e
pnpm audit --audit-level=high
```

Проверяются финансовые инварианты, точность, перезапуск без повторного заполнения, CAS-редактирование, удаление, откаты при превышении лимита и миграции. Два HTTP-сервера с разными соединениями проверяют повторный импорт; браузерные проверки покрывают конфликт и сохранение черновика.

CI устанавливает зависимости по зафиксированным версиям и запускает настроенные проверки. Отдельная проверка документации находит неверные локальные ссылки и изображения. Проверка уязвимостей учитывает известные проблемы на момент запуска.

## Ограничения

- Один локальный оператор: нет банковских подключений, переводов, платежей, аккаунтов и мультивалютного учёта. Категории — пользовательские метки; цель — показатель дохода, а не движок бюджетирования.
- Список показывает 100 последних операций, CSV — до 1000 активных записей. Большим журналам нужны страницы и потоковая выгрузка.
- Перед миграцией существующей БД требуется копия. Некорректные старые суммы и превышения лимита требуют отдельного разбора; приложение не удаляет и не округляет их молча.
- Для совместимости сохранён REAL-столбец счетов, но расчёты используют целые минимальные единицы. Прямые SQL-записи должны заполнять согласованные значения обоих столбцов.
- Проверка Host/Origin не устанавливает личность пользователя. Публичное размещение требует отдельной аутентификации и TLS.
